# 功能列表（Feature List）

**性质**：本文件是**唯一的功能状态清单**。每条功能的状态由**可复现的验证**决定，不由实现者自述决定。
**状态定义**：

| 标记 | 含义 |
|---|---|
| ✅ **可用** | 真实入口（`npm run dev`）运行时，该功能**被接线**且能观察到结果 |
| ⚠️ **部分** | 代码存在，但只覆盖了功能的一部分，或只在只读/离线路径可用 |
| ❌ **缺失** | 代码可能存在（甚至有测试），但**没有任何生产代码调用它** |

**判定方法**（不依赖任何人的自述）：

```bash
# 功能"存在"的判据：生产代码里存在调用点
grep -rn "\.<method>(" src/          # 排除被调用者自身的定义文件
```

**"代码存在 + 测试通过" 不构成 ✅**。本清单记录的是**接线状态**，这正是此前出错的环节。

## 0. 现状总览

```text
发现池 ✅ ──→ 筛选 ✅ ──→ 建仓 ✅ ──→ 监控 ⚠️(估值✅) ──→ 撤池 ✅ ──→ /start（人工）→ 建仓 ✅
                             │                        │
                             └── 查询 ❌               ↓
                                              撤池 ✅（回纯 U 后停 IDLE，等 /start）
                                                    │
                                                    ↓
                                              ↓ 发 /start（人工）
                                              重新建仓（走建仓同一路径）
```

**一句话**：**建仓 + 撤池 + 估值已通过真实资金验收；§4.2.1 口径已实盘打通（fee 单独可见、APR 年化、分母=建仓前U）。** 2026-10-01 首次实盘暴露四类缺陷，2026-10-02 修复并双 DEX 跑通建仓与撤池（含自动换 U）。

⚠️ 的含义：**代码路径存在且被调用，链上未走通或口径未达标** —— 不是"部分实现"，是"未验证"。见 §4.10–4.15。

## 13. 本清单的维护规则

1. **状态只能由可复现的验证改变**，不能由实现者自述改变。
2. 标 ✅ 的功能，必须能在真实入口下演示。
3. **"代码存在 + 测试通过" 不足以标 ✅。**
4. 新增功能时，先加本表条目（❌），实现并接线后改为 ✅。
