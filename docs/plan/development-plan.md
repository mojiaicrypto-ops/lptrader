# 开发计划

**目标**：让产品闭环（[产品文档 §1.1](../product/lptrader-product.md)）**真正可用**。
**唯一验收方式**：真实入口 + dry-run 走到「待广播交易已构造」。见 [产品文档 §7](../product/lptrader-product.md)。
**当前状态**：闭环断在 ③建仓 与 ⑥换池，操作面查询不可用。逐条见 [feature-list.md](../product/feature-list.md)。

## 0. 验收定义（先定死）

```text
一条功能 = 完成，当且仅当：

  经【真实入口】运行时，该功能走到「待广播交易已构造」或「明确的拒绝原因」
  dry-run 模式：构造交易、编码、估算 gas 为止；不签名、不广播

不是：
  ✗ 函数存在        ✗ 单元测试通过
  ✗ typecheck 通过   ✗ 离线算出数字
```

**每次验收记录**：命令、观察到的输出、结论。**不接受自述。**

### 0.1 现有 `dry-run:build` 为何不算验收

`scripts/dry-run-build.ts` **在脚本内自行串起组件**（`PoolScanner → filterPools → planPosition → quoteSwap`），**完全绕过 `runtime.ts`**。

因此它验证的是「这些组件能连起来」，而不是「**运行时把它们连起来了**」。这正是它没抓到「`buildPosition` 生产零调用」的原因。

**结论**：验收必须经过 `buildCadences(runtime)` 所定义的运行时路径。脚本可以是触发器，但**被验证的链路必须是运行时的那一条**。

## 顺序与检查点

```text
P0:  T1 → T2 → T3 → T4
     T5（并行）
          ▼
     检查点 A：你实测 /start → 确认 → 构造出交易
          ▼
P1:  T6 → T7 → T8
          ▼
     检查点 B：你实测 /exit → 自动重建 / 风控触发 → 自动换池
          ▼
P2:  T9 → T10
```

**检查点 A 之前不进入 P1**：建仓链没通就做换池，等于在未验证的地基上加盖。

## 变更纪律

1. 每个任务完成时，更新 [feature-list.md](../product/feature-list.md) 对应条目，**附验收证据**。
2. **未实测不得标 ✅。**
3. 发现新的「写了没接」，**新增条目**，不得绕过。
4. **删除任何"声称会做但没做"的返回文案** —— 文案要么与行为一致，要么不写。
