# 开发计划

**目标**：让产品文档 §1.1 的六步闭环**真正可用**。
**验收方式**：唯一有效的是**真实入口 + dry-run 走到构造完成**（不签名、不广播）。见 [产品文档 §7](../product/lptrader-product.md)。

**当前状态**：闭环断在 ③建仓、⑥换池，且操作面（查询）不可用。详见 [`../product/feature-list.md`](../product/feature-list.md)。

---

## 0. 验收定义（先定死，避免重蹈覆辙）

```text
一条功能 = 完成，当且仅当：

  真实入口运行 → 该功能走到「待广播交易已构造」或「明确的拒绝原因」
  （dry-run：构造交易、编码、估算 gas，到此为止；不签名、不广播）

不是：
  ✗ 函数存在
  ✗ 单元测试通过
  ✗ typecheck 通过
  ✗ 离线算出数字
```

**每次验收必须记录**：执行的命令、观察到的输出、结论。**不接受自述。**

## 执行顺序

```text
P0:  T1 → T2 → T3 → T4          ← 产品能开始
     T5（并行，让你能观察）
P1:  T6 → T7 → T8               ← 闭环成立
P2:  T9 → T10                   ← 指标完整
```

**建议**：T4 完成后**立即让你实测一次**（`/start` → 确认 → 构造交易），确认链路真实，再继续 T6。

## 变更管理

1. **每个任务完成时，更新 `feature-list.md` 的对应条目**，附验收证据。
2. **禁止在未实测的情况下把条目改为 ✅。**
3. 若发现新的"写了没接"，**新增条目**而不是绕过。
4. 删除任何"声称会做但没做"的返回文案 —— **文案要么与行为一致，要么不写**。
